# Honest Limits — BhuLekh-AI Prototype

**Read before citing any numbers from this prototype.**

This document must be shown in the UI "About this prototype" modal and referenced in the demo presentation.

---

## 1. Accuracy

- This system is trained and evaluated **primarily on synthetic data** generated by `tools/synth/generate.py`.
- Synthetic documents simulate real UP khatauni, mutation, and map formats but are **not real documents**.
- Real-world accuracy on actual faded, handwritten, mixed-script state revenue records **will be lower** and must be validated on real data from each state before deployment.
- The numbers shown in the UI (field accuracy, CER, auto-accept rate) come from `tools/eval_pipeline.py` run on the synthetic test split. They are **not production accuracy numbers**.

## 2. Handwriting

- Handwriting recognition is handled by Tesseract and PaddleOCR (ENABLE_TROCR=false by default).
- Handwritten fields routinely receive lower confidence and route to human review — this is expected and shown as a feature (the system knows what it doesn't know).
- Fine-tuned TrOCR for Devanagari handwriting is a roadmap item.

## 3. Unit conversions (bigha, biswa, etc.)

- All state-specific unit values in `data/master/units.yaml` are marked `verified: false`.
- These are **placeholder values** based on commonly cited conversions and must be **verified against each state's revenue code** before use in legal/official contexts.
- The UI Settings page shows these values with a "PLACEHOLDER — verify before use" warning.

## 4. Master data (LGD codes)

- State/district/tehsil/village codes in `data/master/` are **placeholder codes** in the same format as LGD codes but not verified against the official Local Government Directory (lgdirectory.gov.in).
- A real deployment must replace these with verified LGD codes.

## 5. LRMS / DILRMP integration

- The `/mock-lrms` API is a **simulated government system** for demo purposes only.
- Real integration with DILRMP or state LRMS would require state-specific API adapters, credentials, and compliance approvals.
- No real data is pushed to any government system.

## 6. Notifications

- SMS/email notifications are **mocked**. The "Outbox" page shows what would be sent, but no real messages are delivered.
- A real deployment would plug in an SMS gateway (e.g., MSG91) and email service.

## 7. Dashboard history

- Processing statistics shown for the past 30 days are **seeded demo data** (`is_seed=true`).
- The UI shows a "DEMO SEED DATA" badge on all seeded data points.
- Do not present seeded numbers as real production throughput.

## 8. Roadmap items (not implemented in this prototype)

- Keycloak / SSO (using JWT-only auth)
- Neo4j graph DB (using PostgreSQL + networkx)
- GraphQL API (REST only)
- Detectron2 layout detection (using PP-Structure + OpenCV)
- Full TrOCR fine-tuning (flag exists, no weights trained)
- IndicBERT NER (flag exists, disabled by default)
- Encryption at rest (documented as deployment config, not implemented)

## 9. Privacy

- No real personal data is stored or processed in this prototype by default.
- If real organizer sample files are placed in `data/raw/`, handle them per the rules in `data/SOURCES.md`:
  - Do not commit to public repos
  - Mask names in screenshots and slides
  - Use for evaluation only, not training
